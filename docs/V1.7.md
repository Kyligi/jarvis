# J.A.R.V.I.S. V1.7 — Intelligence contextuelle

## Présentation

La V1.7 étend Jarvis avec une analyse contextuelle du bureau
Omarchy, des suggestions intelligentes et des workflows supervisés.

Jarvis reste un assistant local reposant sur Python, PySide6,
Hyprland et les services existants.

## 1. Contexte système

Le module `jarvis.context` permet d'obtenir un instantané du
contexte :

- Application active
- Fenêtre et workspace actifs
- Projet en cours
- Mode enregistré
- Mesures système disponibles
- Erreurs de collecte éventuelles

La collecte est conçue pour continuer à fonctionner lorsqu'une
source facultative est indisponible.

## 2. Suggestions intelligentes

Le moteur `SuggestionEngine` produit des recommandations selon
le contexte observé.

Il prend en charge :

- Les suggestions liées au mode et au projet
- Les diagnostics système
- La priorisation
- Un délai entre les recommandations répétées
- Les suggestions ignorées

Les suggestions sont visibles dans l'accueil du HUD.

Une suggestion ne déclenche pas automatiquement une commande.

## 3. Environnements

Les profils intégrés sont :

- Travail : éditeur et terminal Foot sur le workspace Travail
- Gaming : Steam
- Études : navigateur et Notion

Le détecteur d'environnement distingue :

- `complete` : toutes les applications attendues sont détectées
- `incomplete` : au moins une application manque
- `unknown` : le diagnostic ne peut pas être établi

La restauration passe par les commandes de modes existantes.

Les profils personnalisés par scénarios ne sont pas analysés
comme les profils standards.

## 4. Actions contrôlées

Le module `jarvis.context.actions` utilise une liste fermée
d'actions autorisées.

Le HUD permet :

- Prévisualiser une suggestion
- Confirmer explicitement une action
- Transmettre la commande au CommandBus
- Ignorer une suggestion

Le texte libre d'une suggestion n'est jamais exécuté
directement comme une commande système.

## 5. Workflows supervisés

Les workflows de la V1.7 sont des plans prédéfinis.

Plans disponibles :

### Préparer ma session de travail

1. Activer le mode Travail
2. Effectuer un diagnostic système

### Sauvegarder et vérifier ma session

1. Sauvegarder la session
2. Effectuer un diagnostic système

Le module `WorkflowRunner` supervise l'exécution.

Une seule étape est lancée à la fois. Le passage à la suivante
nécessite une autorisation explicite.

Les résultats sont conservés pendant la session Jarvis.

## 6. Résultats des commandes

CommandBus expose les résultats structurés :

- `success` : réussite établie par une source structurée
- `failed` : échec détecté
- `confirmation_required` : validation supplémentaire nécessaire
- `unknown` : réussite non démontrée

Une réponse textuelle positive n'est pas automatiquement
considérée comme une preuve de réussite.

Les exécutions possèdent un identifiant permettant au workflow
de reconnaître leurs résultats.

## 7. Sécurité des confirmations

Les confirmations de scénarios continuent d'utiliser
leur propre mécanisme sécurisé.

Un workflow ne contourne pas ces confirmations.

Si un scénario attend une validation supplémentaire,
la progression du workflow est bloquée.

## 8. Cycle de vie

Le WorkflowRunner appartient à la session AppContext.

Masquer ou recréer le panneau Workflows ne doit pas entraîner
un nouveau lancement de commande.

Pendant la fermeture complète :

- Les nouvelles commandes sont refusées
- Les nouvelles étapes sont interdites
- Les workers actifs sont attendus
- Les anciennes connexions Qt sont gérées par leur cycle de vie

## 9. Interface

La V1.7 conserve les interfaces Mini et HUD.

Les ajouts se trouvent notamment dans :

- Accueil : contexte et suggestions intelligentes
- Scénarios : workflows supervisés

Les cartes de suggestions sont reconstruites uniquement
lorsque leur contenu change.

## 10. Tests

La V1.7 comprend des tests pour :

- La collecte du contexte
- Les suggestions et les restaurations
- Les actions autorisées
- Les plans et workflows
- Les confirmations
- La corrélation des identifiants d'exécution
- L'annulation et l'arrêt
- Les signaux et workers Qt
- La stabilité des widgets du HUD

Commande de validation :

    uv run python -m pytest -q

## 11. Limites de la V1.7

- Les workflows sont prédéfinis, pas générés librement par l'IA.
- Les résultats textuels peuvent rester `unknown`.
- Les confirmations de scénarios ne sont pas automatisées.
- Un workflow ne garantit pas l'annulation d'une commande déjà
  lancée.
- Les données et états en mémoire du workflow ne constituent
  pas un historique durable entre redémarrages.

Ces limites guideront le développement de la V1.8.
